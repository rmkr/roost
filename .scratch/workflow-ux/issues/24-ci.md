## Question

Add a GitHub Actions workflow for `rmkr/roost` on push and pull request: on Linux run `cargo fmt --all -- --check`, `cargo clippy --locked --all-targets -- -D warnings` and `cargo test --locked` (tests need `/usr/bin/python3`); on macOS and Windows at least build and run clippy so the platform stubs are compiled, and run tests on macOS if they pass (otherwise mark them clearly as not yet expected to pass and say why). Respect `rust-toolchain.toml` (1.97.0). Cache cargo. Never use real Claude or credentials.

## Comments

- 2026-10-06 (Claude subagent ticket-24): Added `.github/workflows/ci.yml` on branch `ticket/24-ci`. Push and pull_request trigger three jobs. Each one reads the channel from `rust-toolchain.toml` and installs it with `dtolnay/rust-toolchain`, then caches with `Swatinem/rust-cache@v2`. The jobs:
  - Linux checks that `/usr/bin/python3` exists, then runs fmt check, clippy `-D warnings` and `cargo test --locked`.
  - macOS runs build and clippy as blocking steps, then `cargo test --locked` with `continue-on-error: true`. Those tests are not expected to pass yet: `tests/cli.rs` reads procfs (`/proc/self/fd/*` in the fake Desktop, `/proc/sys/kernel/hostname`, `/proc/<pid>/stat`), and `src/desktop.rs` only finds Desktop processes through `/proc` on Linux. On macOS runners, `/usr/bin/python3` is the Xcode CLT shim, so the test fixtures don't need changes.
  - Windows runs build and clippy only, since the integration tests are `#![cfg(unix)]`.

  Locally, fmt, clippy and test all pass on Linux with 1.97.0 (offline). The YAML parses with PyYAML. Actions itself hasn't been run, and the Windows and macOS targets aren't installed locally, so whether their clippy is clean is unverified until the first run. Left open until the first Actions run is seen.
