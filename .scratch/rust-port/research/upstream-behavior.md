# Upstream behavior baseline for the Rust CLI

Research ticket: **Establish the upstream behavior baseline**. Researched 2026-10-05. This report establishes facts and unresolved compatibility choices; it does not select the Rust product behavior.

## Revision and evidence

Pinned upstream `main`: [`12909e6fc76cfc3b36861c2b33f998585f2690f8`](https://github.com/CarlosTheory/claude-multi-account/commit/12909e6fc76cfc3b36861c2b33f998585f2690f8), commit “Release 0.1.2” dated 2026-09-16; package version `0.1.2`, executable `ccm`, Node >=18, no runtime dependencies declared. Inspected every runtime module and all three test files. Discovery used an indexed codebase graph and function snippets; file reads filled constant/test coverage gaps. [Package manifest](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/package.json#L1-L26).

Actual verification: Linux, Node v26.10.0, `npm test`: **52 tests, 47 passed, 5 skipped, 0 failed**. Skips cover the macOS Keychain integration test and Windows CMD/PowerShell cases; the macOS hash unit test runs on Linux. Tests use disposable `CCM_HOME` directories and fake `claude`/`security`, while Unix launchers execute through real `sh`. These checks verify the manager’s transformations, not real Claude authentication, account isolation, connectors, updater behavior, or actual Windows/macOS integration. [Sandbox construction](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/test/helpers.js#L10-L75), [launcher execution](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/test/helpers.js#L100-L118), [platform skips](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/test/cli.integration.test.js#L370-L433).

The first restricted-sandbox run failed because `spawnSync` returned `EPERM` and empty output even for a trivial child. An approved run outside that process restriction passed. Six additional disposable-profile probes, also against fake Claude, passed and reproduced the edge cases identified below. No real user profiles, tokens, Keychain entries, shell startup files, registry, or Claude update were accessed by these checks. `setup-path` was inspected only.

## Observable command contract

All ordinary messages use stdout; failures print `ccm: <message>` to stderr and exit 1. `where`/`path` deliberately print only a path plus newline. Ordinary successful commands exit 0. `run` and `update` inherit child stdio and propagate numeric child status; when status is null they return 0, so signal termination has no explicit faithful mapping. [Output/error helpers](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/bin/ccm.js#L50-L62), [child status handling](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/profiles.js#L123-L146), [update](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/bin/ccm.js#L143-L151).

| Command | Source-observed result |
|---|---|
| `add <name>` | Create empty profile and launcher; print data path, launcher, next-login hint. Repeating the same kind regenerates/overwrites launcher without deleting profile data. |
| `add <name> --link-default` | Create marker directory and pass-through launcher; print linked/default explanation. Reject changing an existing normal profile to linked, or vice versa. |
| `add <name> --copy-default` | Print copying progress, copy default data, generate isolated launcher, print independence claim. Reject an existing destination and reject combining the two flags. |
| `list`, `ls` | “No profiles yet…” or root heading and padded name/launcher rows. State precedence: `linked to default`, `token`, `logged in`, `not logged in`. Optional PATH hint. |
| `where <name>`, `path <name>` | Profile path; linked profile returns default Claude directory. Missing/nonexistent name fails. |
| `run <name> [args...]` | Start the shared Claude command with profile environment and all remaining arguments. |
| `token <name>` | Prompt on stdout, visible input; trim stdin token, reject empty input, store token. Linked profiles reject tokens, although validation occurs after reading input. |
| `token <name> --clear` | Delete token if present; print success. Missing profiles and linked profiles fail. |
| `remove <name>`, `rm <name>` | Delete launcher files, retain profile directory/data, print retention/purge hint. |
| `remove <name> --purge` | Delete launcher files and recursively delete profile directory without another prompt; print deleted path. |
| `update` | Print update message and invoke `claude update` against shared installation. |
| `setup-path` | Persist launcher-bin PATH entry; print changed/already-configured note and restart guidance. |
| `doctor` | Run `claude --version`; print binary presence/version, profile/launcher directories, PATH presence, profile names, update/plugin policy; add macOS note there. Missing Claude still produces a successful diagnostic command exit. |
| no arguments; `help`, `-h`, `--help` | Help text including version and usage, successful exit. |
| `-v`, `--version` | Bare package version plus newline. |

Sources for the table: [command implementations](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/bin/ccm.js#L64-L171), [dispatch/aliases](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/bin/ccm.js#L173-L215), [profile creation/removal](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/profiles.js#L65-L120).

The parser is handwritten and permissive: `add` discards every argument beginning `--` when choosing the first name and recognizes its flags by membership. Unknown `--` flags and extra positional arguments are commonly ignored, rather than consistently rejected; `--help` is only a top-level command. No JSON/machine-readable listing, import/export, rename, active-profile selection, profile-specific Claude binaries, shell completions, or config file is implemented. [Dispatch](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/bin/ccm.js#L173-L215).

## On-disk compatibility boundary

`HOME = CCM_HOME || os.homedir()`: manager root `<HOME>/.ccm`, profile directories `.ccm/profiles/<name>`, launchers `.ccm/bin/claude-<name>`, default sources `<HOME>/.claude` and `<HOME>/.claude.json`. Profile names are ASCII letters/digits followed by letters/digits/underscore/hyphen, maximum 32 characters, case preserved; Windows reserved device names and case collisions are not separately rejected. `where` does not call this validator, unlike mutating operations and `run`. [Paths/name rules](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/paths.js#L5-L32), [where](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/bin/ccm.js#L135-L141).

There is **no profile registry, version stamp, ownership identifier, lock, or removal tombstone**. Every actual directory returned by `readdir` is listed; existence defines a profile for command operations. `.ccm-linked-default` presence defines linked kind, regardless of its contents. `.ccm-oauth-token` presence defines token state. Copied profiles have no distinguishing marker and become ordinary isolated profiles. Removing only a launcher leaves a listed, runnable profile and permits launcher regeneration. [Discovery/markers](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/profiles.js#L16-L63), [removal](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/profiles.js#L113-L120).

Copy recursively includes default settings, file credentials, plugins, and history, skipping **top-level** `cache`, `daemon`, `ide`, `paste-cache`, `shell-snapshots`, and `telemetry`; root `.claude.json` is separately copied into the destination. No Keychain secret is copied, no consistency snapshot/lock is taken, and no rollback is provided. Default link creates its own marker directory, never a symlink to `.claude`; purging that normal marker directory leaves default data alone, as tested. [Copy implementation](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/profiles.js#L20-L21), [creation/copy](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/profiles.js#L86-L110), [copy/default-purge tests](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/test/cli.integration.test.js#L163-L229).

## Launching, authentication, and platform differences

Isolated launch paths set `CLAUDE_CONFIG_DIR` to the absolute profile directory, `DISABLE_AUTOUPDATER=1`, and `FORCE_AUTOUPDATE_PLUGINS=1`. If a local token exists, they export `CLAUDE_CODE_OAUTH_TOKEN`; otherwise inherited authentication environment remains present. The manager does not log in itself, validate a token, or determine the effective account. [Launchers](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/shims.js#L20-L58), [direct run](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/profiles.js#L123-L164).

Linux/macOS generate one `#!/bin/sh` launcher (creation mode 0755, `exec claude "$@"`). Windows generates extensionless sh, `.cmd`, and `.ps1` variants; sh replaces path backslashes with slashes, CMD forwards `%*`, PowerShell forwards `@args` and exits `$LASTEXITCODE`. All call whichever `claude` resolves on PATH. Direct Windows execution uses `where.exe claude`, takes the first executable `.exe`/`.com` or `.cmd`/`.bat` in PATH order, and explicitly routes batch files through `cmd.exe /d /s /c`; Unix uses a direct `claude` spawn. [Shim templates/files](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/shims.js#L20-L102), [resolver](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/claude-bin.js#L1-L25).

Login display is a heuristic: `.credentials.json` existence suffices even for `{}`. On macOS only, `security find-generic-password -s <service>` succeeds or fails with output ignored; service is `Claude Code-credentials-` plus the first eight hex characters of SHA256 of the raw profile path. It does not read the secret or validate expiry/account. Token input is echoed; new token files request Unix mode 0600, without explicit Windows ACL handling. [Login detection](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/profiles.js#L27-L59), [hash](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/paths.js#L34-L41), [token prompt/storage](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/bin/ccm.js#L120-L133), [token write](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/profiles.js#L150-L164).

`setup-path` on Windows reads/writes user-scoped `Path` through PowerShell and appends the bin directory. Unix appends an export to each existing `.zshrc`, `.bashrc`, `.profile` unless its text already contains `/.ccm/bin`; fallback creates/appends `.profile` when no file was updated and current PATH lacks the bin. This uses **real `os.homedir()` and literal `$HOME/.ccm/bin`, ignoring `CCM_HOME`**. PATH detection lowercases resolved paths even on case-sensitive systems. No removal/uninstall cleanup is implemented. [PATH behavior](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/pathenv.js#L7-L64).

## Discrepancies and choices this evidence exposes

1. **Effective authentication versus apparent login.** Disposable probe reproduced inherited OAuth token use by an isolated profile with no local token. File/Keychain existence cannot prove the chosen account. The Rust specification must settle inherited auth/provider precedence and the meaning of list state. Upstream README's broad isolation wording is not an execution guarantee. [Environment code](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/profiles.js#L128-L142), [README claim](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/README.md#L7-L18). Official Claude contracts require separate investigation; this report does not treat upstream’s inferred Keychain hash as a supported external API.
2. **Linked launcher/run mismatch.** Probe with inherited `CLAUDE_CONFIG_DIR=/tmp/foreign-config` reproduced preserved config in the launcher but removed config in `ccm run linked`; both inherited token and updater values. The “environment left untouched” test starts from helpers that delete these variables, masking the distinction. [Linked templates](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/shims.js#L60-L75), [run deletion](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/profiles.js#L128-L132), [test env neutralization](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/test/helpers.js#L78-L88).
3. **Update environment is inherited.** Probe reproduced foreign config and `DISABLE_AUTOUPDATER=9` reaching `claude update`; the test’s “outside any profile” wording holds only with neutralized fixture environment. No manager-level update lock exists. [Implementation](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/bin/ccm.js#L143-L151), [test](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/test/cli.integration.test.js#L356-L367).
4. **Copy failure and macOS login claim.** Probe reproduced missing default source leaving an empty profile directory; retry then refuses overwrite. Test “fails cleanly” checks only exit/message, not rollback. Copy cannot transport a default Keychain login because it only copies files, despite prose saying the current account is copied. Rust copy semantics need to distinguish data seeding from credentials and define partial-operation recovery. [Creation order](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/profiles.js#L86-L106), [narrow failure test](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/test/cli.integration.test.js#L188-L197), [account prose](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/bin/ccm.js#L79-L85).
5. **Token replacement permissions.** Probe precreated a token file with mode 0644, replaced it using `token`, and reproduced retained 0644. Mode 0600 is only requested on creation; the test checks a new file. Secret input, replacement permissions, Windows protection, and inherited token behavior need an explicit contract. [Write](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/profiles.js#L150-L164), [new-file test](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/test/cli.integration.test.js#L243-L253).
6. **Coexistence needs an ownership rule.** Both managers could read the same simple profile format, but upstream overwrites/deletes matching launcher paths without an ownership check and has no coordination locks. Safe coexistence must decide launcher names/ownership, shared-data mutation, purge safeguards, malformed/linked filesystem entries, and rollback; reading existing profiles alone does not establish safe concurrent writing. [Writes/deletes](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/shims.js#L82-L102), [profile mutation](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/profiles.js#L65-L120).
7. **Parsing/path/argument edge coverage is incomplete.** Probe confirmed `add accepted --unknown` succeeds. Templates interpolate absolute directory strings into shell quotes without shell-specific escaping; unusual home paths and Windows arguments need real interpreter tests. The fake Claude joins arguments into one string, so existing tests do not establish preservation of all argument boundaries. `setup-path`, signals, interrupted operations, concurrent writes, and Windows reserved names have no dedicated tests here. [Parser](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/bin/ccm.js#L173-L215), [templates](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/src/shims.js#L20-L58), [fake argument output](https://github.com/CarlosTheory/claude-multi-account/blob/12909e6fc76cfc3b36861c2b33f998585f2690f8/test/helpers.js#L21-L32).
